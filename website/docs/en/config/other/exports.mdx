# exports

- **Type:** `boolean | ExportsOptions`
- **Default:** `false`
- **CLI:** `--exports` / `--no-exports`

Generate the `exports` field in `package.json` from the build outputs after a successful build. Set it to `true` or an object to enable it, and use the object to pass the options below.

```ts title="rslib.config.ts"
export default defineConfig({
  lib: [{ format: 'esm', dts: true }],
  exports: true,
});
```

`exports` can only be set at the top level, not in a `lib` item. The generated result replaces the existing `exports` as a whole. Add extra subpaths with [exports.custom](#exportscustom). It is not generated in watch mode, or when only some libs are built with `--lib`.

## Generation rules

- Only outputs in the `esm` and `cjs` formats are exported.
- The `index` entry is exported as `.`, `button/index` as `./button`, and other entries by their names.
- When an entry has both `esm` and `cjs` outputs, the `import` and `require` conditions are used. With a single format, the output path is used directly.
- For libs with [dts](/config/lib/dts) enabled, declaration files are exported as well, with a `types` condition when TypeScript cannot find them on its own.
- In bundle mode, the CSS files of the entries are exported. In bundleless mode, they are not.

For example, building `esm` and `cjs` libs with an `index` entry generates:

```json title="package.json"
{
  "exports": {
    ".": {
      "import": "./dist/esm/index.js",
      "require": "./dist/cjs/index.cjs"
    }
  }
}
```

## exports.include

- **Type:** `string[]`
- **Default:** all entries in bundle mode, `index` in bundleless mode

The outputs to export, as glob patterns matched against the output paths relative to the output directory. The extension can be omitted.

For example, to export the main entry and the `index` of each component directory in bundleless mode:

```ts title="rslib.config.ts"
export default defineConfig({
  lib: [{ format: 'esm', bundle: false }],
  exports: {
    include: ['index', '*/index'],
  },
});
```

## exports.exclude

- **Type:** `string[]`
- **Default:** `[]`

The outputs to exclude from those selected by `include`, in the same format as `include`.

## exports.source

- **Type:** `boolean | string`
- **Default:** `false`

Export the source files of the entries, so that the source code can be used directly during development.

- `true`: `exports` points to the source files, and the exports of the build outputs are written to `publishConfig.exports`.
- A string: a condition with this name pointing to the source file is added to each JavaScript subpath, which can be used with the [customConditions](https://www.typescriptlang.org/tsconfig/#customConditions) option of TypeScript or [@rsbuild/plugin-source-build](https://github.com/rstackjs/rsbuild-plugin-source-build).

For example, `source: '@acme/source'` generates:

```json title="package.json"
{
  "exports": {
    ".": {
      "@acme/source": "./src/index.ts",
      "default": "./dist/index.js"
    }
  }
}
```

## exports.custom

- **Type:**

```ts
type ExportsCustomItem =
  | ExportsField
  | ((
      exports: ExportsField,
      context: { pkg: Record<string, unknown>; isPublish: boolean },
    ) => ExportsField | Promise<ExportsField>);

type ExportsCustom = ExportsCustomItem | ExportsCustomItem[];
```

- **Default:** `undefined`

Customize the generated result.

- An object: adds subpaths, replacing generated ones with the same name.
- A function: receives the generated result and returns the final exports. When `source` is `true`, it is called again for `publishConfig.exports` with `isPublish` set to `true`.
- An array: each item is applied in order.

```ts title="rslib.config.ts"
export default defineConfig({
  exports: {
    custom: (exports) => ({
      ...exports,
      './package.json': './package.json',
    }),
  },
});
```
