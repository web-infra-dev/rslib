# 默认行为

Rslib 基于 Rsbuild 和 Rspack，并针对库构建场景调整了一些默认行为。

这些默认行为通常取决于 [format](/config/lib/format)、[bundle](/config/lib/bundle)、[output.target](/config/rsbuild/output#outputtarget) 等配置，以及 `package.json` 和 `tsconfig.json` 文件中的部分属性，你可以通过配置和插件调整这些行为。

## 环境变量 \{#environment-variables}

Rslib 在构建库代码时，会根据 [format](/config/lib/format) 选择将源代码中的 `process.env.NODE_ENV` 表达式保留在产物中，或在构建时替换为指定值：

| 产物格式       | 默认行为                                                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `esm` / `cjs`  | 保留表达式，交给使用方的应用在二次构建时替换和优化，或在直接运行时根据实际环境变量选择分支。                                                    |
| `umd` / `iife` | 直接加载，在库构建时替换为构建进程的 `NODE_ENV`，默认为 `'production'`。                                                                        |
| `mf`           | 直接加载，默认在 [mf-dev](/guide/basic/cli#rslib-mf-dev) 时替换为 `'development'`，在 [build](/guide/basic/cli#rslib) 时替换为 `'production'`。 |

你可以通过 [source.define](/config/rsbuild/source#sourcedefine) 显式指定替换值，或通过 [tools.rspack](/config/rsbuild/tools#toolsrspack) 配置 Rspack 的 [optimization.nodeEnv](https://rspack.rs/zh/config/optimization#optimizationnodeenv) 来调整或关闭替换。

有关其他预设环境变量、`.env` 文件的加载规则及变量替换方式，请参阅 [环境变量](/guide/advanced/env-vars)。

## 格式、入口和依赖

不同 [format](/config/lib/format) 对应的默认设置如下：

| 格式   | [output.target](/config/rsbuild/output#outputtarget) | [output.autoExternal](/config/rsbuild/output#outputautoexternal) | 支持 [bundle: false](/config/lib/bundle#bundle-false) |
| ------ | ---------------------------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------- |
| `esm`  | `'node'`                                             | `true`                                                           | 是                                                    |
| `cjs`  | `'node'`                                             | `true`                                                           | 是                                                    |
| `umd`  | `'node'`                                             | `false`                                                          | 否                                                    |
| `iife` | `'node'`                                             | `false`                                                          | 否                                                    |
| `mf`   | `'web'`                                              | `false`                                                          | 否                                                    |

:::note
`output.autoExternal` 对 JavaScript 依赖的自动 external 仅在 bundle 模式下生效。
:::

[format](/config/lib/format) 和 [output.target](/config/rsbuild/output#outputtarget) 分别指定模块格式和目标运行环境。构建面向浏览器的库时，将 `output.target` 设置为 `'web'`，MF 格式还需要添加 [Module Federation 插件](/guide/advanced/module-federation#快速开始)。

结合产物格式、目标环境和 [bundle](/config/lib/bundle) 配置，Rslib 对入口、目录结构和依赖采用以下默认处理：

| 功能             | 默认行为                                                                                                                                                                                                          | 相关链接                                                                                                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入口             | bundle 模式查找 `src/index`；bundleless 模式匹配 `src/**`，保留文件结构。                                                                                                                                         | [source.entry](/config/rsbuild/source#sourceentry)、[bundle](/config/lib/bundle)                                                                                                                                  |
| 目录结构         | bundleless 模式以输入文件（不含类型声明文件）的最长公共目录为基础，保留相对目录结构。                                                                                                                             | [outBase](/config/lib/out-base)                                                                                                                                                                                   |
| 模块引用         | bundleless 模式将本地 JS、样式和资源引用改为相对产物路径，并补全或替换扩展名；包名引用保留。                                                                                                                      | [redirect.js](/config/lib/redirect#redirectjs)、[redirect.style](/config/lib/redirect#redirectstyle)、[redirect.asset](/config/lib/redirect#redirectasset)                                                        |
| 自动 external    | bundle 模式下，ESM/CJS 将 `dependencies`、`optionalDependencies`、`peerDependencies` 及其子路径设为 external，不含 `devDependencies`。                                                                            | [output.autoExternal](/config/rsbuild/output#outputautoexternal)、[output.externals](/config/rsbuild/output#outputexternals)                                                                                      |
| external 类型    | ESM：`modern-module`；CJS：`commonjs-import`；UMD：`umd`；IIFE/MF：`global`。                                                                                                                                     | [output.externals](/config/rsbuild/output#outputexternals)、[externalsType](https://rspack.rs/zh/config/externals#externalstype)                                                                                  |
| Node.js 内置模块 | `output.target` 为 `'node'` 时，设置 `externalsPresets.node: false`，显式将内置模块设为 external，使其使用对应格式的 `externalsType`，匹配 `import` / `require` 的引用语义；不受 `output.autoExternal` 开关影响。 | [output.externals](/config/rsbuild/output#outputexternals)、[externalsPresets.node](https://rspack.rs/zh/config/externals#externalspresets)、[externalsType](https://rspack.rs/zh/config/externals#externalstype) |

## 优化和分包

Rslib 通过 Rsbuild 的 [mode](https://rsbuild.rs/zh/config/mode) 配置选择构建和优化策略：

- `rslib` 和 `rslib --watch` 使用 `'production'`，watch 只增加文件监听和重新构建。
- `rslib mf-dev` 使用 `'development'`，用于 MF 开发服务。

`mode` 是独立于构建进程 `NODE_ENV` 的配置。例如，执行 `NODE_ENV=development rslib` 时，构建仍使用 `mode: 'production'`。

Rslib 在此基础上调整了以下优化默认值：

| 功能         | 默认行为                                                                                                                                                                                                                                  | 相关链接                                                                                                                                                                                                                                                                                                     |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 压缩         | 生产模式下清理死代码和未使用代码，保留变量名和 Pure 注解。<br />ESM/CJS/UMD/IIFE 保留代码格式；MF 删除多余的空白和换行，并关闭顶层未使用代码消除，以保留 remote entry 全局变量。                                                          | [output.minify](/config/rsbuild/output#outputminify)                                                                                                                                                                                                                                                         |
| 分包         | `splitChunks.preset: 'none'`；ESM/CJS 仅从异步 chunk 提取公共代码；UMD/IIFE 关闭分包和异步 chunk。                                                                                                                                        | [splitChunks](https://rsbuild.rs/zh/config/split-chunks)、[optimization.splitChunks](https://rspack.rs/zh/config/optimization#optimizationsplitchunks)、[output.asyncChunks](https://rspack.rs/zh/config/output#outputasyncchunks)                                                                           |
| 模块 ID      | 非 MF 格式：`output.target` 为 `'node'` 时使用 `'named'`，便于调试；`output.target` 为 `'web'` 时使用 `'deterministic'`，保持 ID 稳定。<br />MF：`mode` 为 `'production'` 时使用 `'deterministic'`，为 `'development'` 时使用 `'named'`。 | [optimization.moduleIds](https://rspack.rs/zh/config/optimization#optimizationmoduleids)                                                                                                                                                                                                                     |
| Chunk ID     | 沿用 Rspack：生产模式使用 `'deterministic'`，开发模式使用 `'named'`。                                                                                                                                                                     | [optimization.chunkIds](https://rspack.rs/zh/config/optimization#optimizationchunkids)                                                                                                                                                                                                                       |
| ESM 产物优化 | `concatenateModules: false`、`sideEffects: true`、`avoidEntryIife: true`，配合 `modern-module` 输出，便于下游 tree shaking。                                                                                                              | [optimization.concatenateModules](https://rspack.rs/zh/config/optimization#optimizationconcatenatemodules)、[optimization.sideEffects](https://rspack.rs/zh/config/optimization#optimizationsideeffects)、[optimization.avoidEntryIife](https://rspack.rs/zh/config/optimization#optimizationavoidentryiife) |
| 共享 runtime | ESM 在 bundleless 或多个显式入口时设置 `runtimeChunk: { name: 'rslib-runtime' }`，复用运行时代码。                                                                                                                                        | [optimization.runtimeChunk](https://rspack.rs/zh/config/optimization#optimizationruntimechunk)                                                                                                                                                                                                               |

:::note

- 手动设置 `output.minify` 会**替换整套默认压缩配置**，即使只设置对象中的部分选项，也不会继承上述预设。`output.minify: false` 只关闭压缩器，Rspack 仍会分析导出的使用情况和副作用，但可能保留未使用的声明。
- `splitChunks.preset: 'none'` **不保证只生成一个文件**：动态导入、多个入口、Worker 和运行时代码都可能产生额外文件。

:::

## 类型声明

Rslib 默认不生成类型声明文件。开启 `dts: true` 后，默认生成未打包的类型文件，与 JavaScript 的 `bundle` 设置无关。多份 JavaScript 产物可以共用类型文件，通常只需在一个 `lib` 项中开启 `dts`。

## 调整和检查配置

所有产物共用的配置放在顶层，单个产物的配置放在对应的 `lib` 项中。`lib` 中的配置优先于顶层配置，再由这些配置决定对应的默认处理。CLI 中显式指定的构建参数会覆盖配置文件中的对应选项，详见 [CLI](/guide/basic/cli)。

对象通常递归合并，数组通常追加；`resolve.extensions` 等选项则整体覆盖，具体规则见 [配置合并规则](https://rsbuild.rs/zh/api/javascript-api/core#合并规则)。通过 [mergeRslibConfig](/api/javascript-api/core#mergerslibconfig) 合并多份配置时，`lib` 中相同 `id` 的项会合并，没有 `id` 的项会追加。

表格中的 Rspack 配置项可以通过 [tools.rspack](https://rsbuild.rs/zh/config/tools/rspack) 调整，用法请查看该配置文档，其他 Rslib 与 Rsbuild 配置项可以查看 [配置总览](/config/)。

你可以开启 [调试模式](/guide/basic/configure-rslib#调试模式)，或运行 [rslib inspect](/guide/basic/cli#rslib-inspect) 命令来查看最终生成的配置。
